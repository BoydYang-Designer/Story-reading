整體評估

這個網頁應用是一個功能豐富的英語學習工具，包含閱讀、筆記、測驗、成績儀表板和音檔時間編輯等模組。 整體程式碼結構完整，開發者已針對多個已知 Bug（BUG-01 ~ BUG-11）進行過修正， 顯示有持續維護的習慣。

主要風險集中在三個方向： （1）API Key 直接寫死在 HTML 前端（Firebase 金鑰暴露）、 （2）部分功能高度依賴外部服務（GitHub Raw / Firebase），離線或網路不穩時體驗劇降、 （3）LocalStorage 為主的資料儲存沒有配額保護，若單字筆記或 Quiz 記錄過多可能導致寫入失敗且無提示。

建議優先處理安全性問題（Firebase Key 移至後端環境變數），再逐步補強錯誤提示與離線降級邏輯。

主要風險項目
🔴 高風險 Firebase API Key 直接暴露在前端 HTML 原始碼
在哪裡：index.html 第 1571–1582 行
問題：任何人打開瀏覽器的「查看原始碼」就可以看到完整的 Firebase 設定，包含 apiKey、appId、measurementId 等。雖然 Firebase 有安全規則可以限制讀寫，但暴露的 Key 可能被用來發動服務拒絕攻擊（大量讀寫消耗你的配額）或被其他人設定自己的規則繞過。
建議：將 Firebase 初始化移至後端（如 Cloud Functions），前端透過後端 API 取得 token，或至少在 Firebase Console 設定嚴格的 App Check 和安全規則。
🔴 高風險 匯入 JSON 時缺乏資料驗證，可能覆蓋現有資料
在哪裡：data-manager.js 匯入功能
問題：用戶匯入一個格式錯誤或惡意構造的 JSON 時，程式只做最基本的 JSON.parse，沒有驗證資料結構是否符合預期格式，可能直接覆蓋掉現有的筆記資料。
建議：匯入前先備份現有資料（或提示用戶先匯出），並加入 JSON Schema 驗證，只允許符合格式的資料匯入。
🟠 中風險 LocalStorage 超出配額時靜默失敗，用戶不知情
在哪裡：story.js / timestamp-editor.js / scores-dashboard.js 的 localStorage.setItem 呼叫
問題：LocalStorage 上限約 5MB。當筆記、Quiz 分數、Timestamp Override 累積過多，setItem 會拋出 QuotaExceededError。目前大多數地方沒有用 try-catch 包住，一旦失敗資料就不見了，但用戶不會看到任何錯誤提示。
建議：所有 localStorage.setItem 加上 try-catch，超出配額時主動彈出提示，引導用戶清理或匯出。
🟠 中風險 Voice Reorder 語音辨識只在 Chrome 可用，無相容性提示
在哪裡：quiz.js Voice Reorder 模式
問題：Web Speech Recognition API 只有 Chrome（桌機）完整支援，Safari 部分支援，Firefox 不支援。用戶在 Safari/Firefox 點擊麥克風可能沒有反應，但介面上沒有任何說明或提示。
建議：進入 Voice Reorder 前偵測 API 是否可用，若不可用顯示「此功能需要 Chrome 瀏覽器」的提示，而非讓用戶自己猜。
🔵 低風險 自訂文章 Slug 可能重複，造成 ID 衝突
在哪裡：story.js 自訂文章功能
問題：若用戶新增兩篇標題相似的文章（例如「test」和「Test」），生成的 Slug 可能相同，導致後者覆蓋前者的資料。
建議：儲存時檢查 Slug 是否已存在，若衝突則自動加上數字後綴（如 test-2）或提示用戶修改標題。
💡 改善建議（按優先序）
  • 🔒 把 Firebase 設定移出前端 HTML — 使用環境變數或後端代理，避免 API Key 直接暴露給所有訪客。 P0 · 立即處理
  • 💾 為所有 localStorage.setItem 加 try-catch — 超出配額時顯示友善提示，引導用戶清理或匯出備份，防止靜默資料遺失。 P1 · 重要
  • 📥 匯入前加入資料驗證與備份提示 — 驗證 JSON 結構，並提示用戶先匯出再匯入，防止資料被覆蓋。 P1 · 重要
  • 🎤 Voice Reorder 加入瀏覽器相容性偵測 — 非 Chrome 環境顯示提示，說明此功能需要 Chrome，避免用戶一頭霧水。 P2 · 建議
  • 🔇 音訊載入失敗加入明確提示 — 目前音訊載入失敗只有 console 錯誤，建議在文字容器上方顯示「音訊無法載入，請檢查網路連線」的提示。 P2 · 建議
  • 🆔 自訂文章 Slug 唯一性保護 — 儲存前驗證 Slug 是否重複，衝突時自動加後綴或提示更改標題。 P3 · 可改善
  • 📱 為 Dictation 模式加入「播放失敗」的用戶提示 — iOS Chrome 的 Web Speech API 靜音 Bug 已有 timeout 偵測，但建議加上視覺提示告知用戶「語音播放異常，請點擊重試」。 P3 · 可改善
